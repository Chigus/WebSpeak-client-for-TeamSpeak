# 本 fork 相对原版的新增内容

[返回项目首页](../README.md) · [中文使用文档](./README.zh-CN.md) · [部署与更新](./FORK_DEPLOYMENT.zh-CN.md)

本仓库是 [EchoSixHIYA/WebSpeak-client-for-TeamSpeak](https://github.com/EchoSixHIYA/WebSpeak-client-for-TeamSpeak) 的维护版 fork。下述比较以派生时的 **WebSpeak 0.2.6**、上游提交 [35dde81](https://github.com/EchoSixHIYA/WebSpeak-client-for-TeamSpeak/commit/35dde81cc2964e49248f60732ac3dfb9de646f7f) 为基准，不代表上游未来版本的能力。

维护分支为 `nas/macau`，当前功能版本为 `0.2.6-stereo.7`。版本号相同的提交也可能包含不同的文档或构建改动，确认部署版本应核对完整 Git SHA。

## 人头麦 / 立体声原音

入口：**音频设置 → 输入模式 → 人头麦 / 立体声原音**。Studio One 等 DAW 需先经声卡回录或立体声虚拟录音设备将独立 L / R 提供给浏览器，再选择对应输入设备。

这个模式关闭浏览器回声消除、降噪、自动增益及输入 RNNoise，并绕过 VOX 音量门限。未闭麦且未进行本地录音测试时持续发送。不能把单声道复制到左右并当作真实人头麦声场；需要实际检查声卡 / DAW 跳线，并使用耳机验证左右声道。

TeamSpeak 路径使用 48 kHz、20 ms 帧和 codec 5（Opus Music），强制两声道、192 kbps CBR，每个 Opus 包为 480 字节。这是有损 Opus；网页到网关的双声道 PCM 上行约 1.54 Mbps，另有协议开销。原版网关 WebRTC 混音器仍为单声道，立体声部署保持它关闭。普通单声道路径保留。

详见 [人头麦与立体声输入](./STEREO.zh-CN.md)。

## 输入与接收独立三档 RNNoise

入口：**音频设置 / 音频栏 → 输入降噪、接收降噪**。两组分别控制开关及轻度、中度、重度，设置保存在当前浏览器的 IndexedDB 中。

输入处理自己的麦克风；接收仅改变自己听到的成员音频。重度增加低频高通、50 / 60 Hz 稳定谐波检测和基于模型语音概率的残余噪声衰减。接收默认关闭，开启后左右声道拥有独立模型状态。立体声原音模式始终绕过输入降噪。

模型沿用依赖 `@sapphi-red/web-noise-suppressor` 的 RNNoise WASM，不是本 fork 自训练模型。新增的是双向处理、档位控制、滤波和运行生命周期；推理成功后才显示生效，失败保留或恢复原音。处理不能恢复已经失真的人声，也不保证完全消除所有电流噪声。

## 小规模网页语音 P2P

入口：**音频设置 → 网页 P2P 语音**。同一网关、同一 TeamSpeak 服务器、同一频道的网页用户分别主动开启；默认关闭，不跨页面保存开启状态。2～5 位开启者形成小规模 mesh，第六位加入时全部回到服务器路径。

新增语音直连与原版 P2P 屏幕共享、网关 WebRTC 混音是三个不同功能。音频通过 WebRTC DataChannel 传输 48 kHz Int16 PCM，支持独立左右声道、序号去重和迟到帧丢弃。控制与频道成员资格仍依赖已认证的 WSS 会话，切换频道或离开会释放直连。

原生 TeamSpeak、未开启者和私语继续走服务器。直连成功时抑制重复播放，失败后使用服务器备用音频；接收租约最长 500 ms，回退还涉及播放预缓冲，不是零延迟无缝切换。

每位直连听众额外消耗约 0.8 Mbps 单声道或 1.6 Mbps 双声道上行，同时仍保留 WSS 上行。网络地址会向对端暴露，NAT / ICE / TURN 条件会影响连通性。直接通话不经过 TeamSpeak 的发言权过滤，依赖服务端发言审批的频道应关闭 P2P。

完整信令、降噪和回退说明见 [双向降噪与网页 P2P](./PEER_VOICE_AND_DENOISING.zh-CN.md)。

## 网页频道音乐

入口：**语音频道 → 音乐图标 → 搜索 / 我的歌单 / 播放队列**。支持网易云与 QQ 搜索及公开歌单、网易云短分享文字、逐曲点歌、每页最多 100 首批量添加、暂停 / 切歌、音量及随机 / 循环。机器人在 TeamSpeak 中播放，频道所有人听同一份队列。

TSBot 官方项目提供音源解析、平台授权、语音机器人及独立管理网页；本 fork 提供嵌入式播放器、WSS 请求协议、真实频道成员资格校验和私有服务部署模板。音乐服务与平台授权需要额外安装和配置，会员 / 版权 / 地区限制仍适用，QQ 短链需先展开为完整歌单链接。浏览器保存歌单 ID 和名称，不自动读取所有成员的账号歌单。

详见 [频道音乐使用、限制与部署](./CHANNEL_MUSIC.zh-CN.md)。

## 中转、NAS 与本 fork 部署

- [深圳语音中转](./SHENZHEN_RELAY.zh-CN.md)：`scripts/shenzhen-relay/` 提供 nginx HTTPS/WSS 和 TS UDP 转发、DNS-01 证书签发 / 续期、配置验证、版本发布及 ASUS 精确端口转发 / 回退。转发不转码音频；实例域名、局域网地址及端口需按自己的网络调整，不包含现成的中转基础设施。
- [NAS Git 发布](./NAS_GIT_DEPLOYMENT.zh-CN.md)：`scripts/nas/` 从明确的干净提交归档构建，保留立体声历史，验证真实 Opus 左右分离，保存旧镜像 / 配置并在切换失败时回退；运行数据和凭据留在 checkout 外。
- [部署与更新](./FORK_DEPLOYMENT.zh-CN.md)：默认 Compose 从当前源码构建，也可使用 `docker-compose.image.yml` 拉取 `ghcr.io/chigus/webspeak`。amd64 / arm64 分别在原生执行器构建，两边验证成功后才更新多架构标签；完整 SHA 标签用于锁定版本。
- 对应源码：镜像和 NAS 发布流程提供 `/source/webspeak-stereo-source.tar.gz`，包含本 fork 源码、测试、锁文件和构建脚本；不包含运行数据、私钥或登录凭据。

**更新边界：** 推送 GitHub、发布镜像、更新运行实例是不同步骤。`latest` 只指向最新成功构建；已有实例需要拉取 / 构建并重建容器，Node.js 源码部署也需要重新构建和重启。Release 是发布时的快照。单独推送或修改代码不会自动更新所有人的服务器。

## 验证范围

新增回归测试覆盖立体声采集 / 编码 / 播放、真实 RNNoise 模型及档位、左右分离、信令成员隔离、去重、回退、私语路径和资源释放。已有验证还包括本地 Chrome 双页面、经深圳公网入口的浏览器信令 / 直连，以及真实 TeamSpeak 路径的合成立体声音频。

浏览器双页面测试在同一台 Windows 机器上进行，不能作为异地运营商或所有 NAT 都可穿透的证明。合成音频、模型 active 状态和 HTTP 健康检查不能代替物理人头麦、具体声卡、损坏麦克风或嘉兴等听众线路的实测听感。

## 屏幕共享选择线路

进入频道 → 点击共享屏幕 → 选择「P2P 直连」「澳门服务器」或「深圳服务器」→ 选择分辨率、帧率并开始。未部署的节点显示为不可用，默认保留 P2P；选择会保存在本机。观看画面显示当前线路。节点由共享者选择，与打开网站时使用的入口域名无关。

服务器线路使用 TURN 转发，画面强制经过选定节点；连接失败需要重新共享或换线路，不会自动改为 P2P。每次共享的临时授权为 24 小时，超时后新观众加入需重新共享。此功能并非 SFU，仍随观看人数增加共享者上传流量。部署参数、网络限制与撤销方法见 [TURN 节点说明](../scripts/screen-relay/README.md)。
