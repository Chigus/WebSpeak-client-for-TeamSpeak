# 人头麦与立体声输入

此版本基于 WebSpeak 0.2.6，新增可选的立体声输入与立体声播放。发送端的「音频设置 → 输入模式」可选择「人头麦 / 立体声原音」。听众的网页会自动按收到的音频声道播放。

Studio One 等 DAW 的主输出需通过声卡回录或立体声虚拟音频设备，提供给浏览器作为录音输入。例如，使用 ASIO 跳线输出到「daw麦克风」时，在网页的输入设备中选择该录音设备，并确认 DAW 的左、右输入分别进入输出 L、R。

立体声模式请求双声道输入，关闭浏览器回声消除、降噪、自动增益和 RNNoise，不使用语音音量门限。未静音且未进行本地录音测试时持续传送声音。页面显示左右独立电平；浏览器报告的输入声道数与实际配置的发送声道数也会显示。无法提供双声道的设备会报错，不会把单声道复制两份并声称保留了人头麦声场。

建议使用耳机收听，在系统辅助功能中关闭「单声道音频」，并依次测试左、右麦克风。输入显示两个声道并不证明 DAW 中的左右信号已经独立；需检查跳线并由听众分别确认左右声音。

## 音频链路

- 浏览器在 48 kHz 的 AudioContext 中处理音频，每 20 ms 发送一帧。
- 普通语音：每帧 1,920 字节、960 个 Int16 单声道样本，使用 TeamSpeak Opus Voice（codec 4）。
- 立体声：每帧 3,840 字节、每声道 960 个 Int16 样本，顺序为 L0、R0、L1、R1。网关使用双声道 Opus Music（codec 5），码率 192 kbps，并保持双声道编码。
- TeamSpeak 音频下行保留编码包；网页按 codec 4 或 5 创建单声道或双声道解码器。
- 这是有损 Opus 音频，不是无损 PCM 传输至听众。浏览器到网关的立体声 PCM 上行约为 1.54 Mbps，另有传输开销。

部署时应关闭 WebSpeak 的 WebRTC 语音选项：原有 WebRTC 混音器仍为单声道。此部署使用 HTTPS/WSS 5555，无需新增端口。TeamSpeak 的目标频道建议配置为 Opus Music，并让所有收听者加入同一频道；普通私语权限与服务器人数限制继续适用。

## 验证与源码

单元和集成测试包含左右单独输入、反相信号、交错帧边界、采集模式切换、真实 Opus 双声道编码及播放资源释放。真实 TeamSpeak 和具体人头麦的验证需另行记录，不能用 HTTP 健康检查代替。

本项目使用 AGPL-3.0-only。部署时将此修改版的对应源代码存档提供于 `/source/webspeak-stereo-source.tar.gz`，主页提供下载链接。存档不应包含运行数据、密码、私钥或 node_modules；完整源代码和依赖锁文件足以按仓库文档构建。
