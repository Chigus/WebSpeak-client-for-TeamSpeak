本文记录 `webspeak-webclient` 的当前代码边界、待修改事项、大致修改方向及验收标准。最初仅整理文档，后续根据施工目标分批实施；当前进度与验证边界见下文。

当前构建与 CI 基线已经建立，共享协议已迁移并通过本地验证，屏幕共享已从前端语音核心拆出。后续继续补齐媒体与会话行为验证、拆分其他前后端核心职责和页面；Android 平台验证与本地产物整理分别推进。

## 当前代码边界

| 部分 | 主要位置 | 职责 |
| --- | --- | --- |
| 网关启动与 HTTP | `src/index.ts`、`src/server/server.ts` | 初始化服务、公共接口、加入凭证、静态页面和管理路由 |
| 实时会话与协议桥接 | `src/server/voice-bridge.ts`、`session-manager.ts`、`voice-protocol.ts` | 会话生命周期、命令分发、语音、事件同步和屏幕共享信令 |
| 共享协议 | `src/shared/` | 前后端消息模型、命令载荷、屏幕共享解析、服务端消息校验和皮肤目录类型 |
| TeamSpeak 接入 | `src/server/ts-client.ts`、`teamspeak-adapter.ts`、`directory-sync.ts` | SDK 适配、连接、目录同步、聊天及语音收发 |

| 浏览器媒体控制 | `web/src/voice/` | 已拆出的屏幕共享采集、协商、资源清理及诊断 |

连接主链路为：浏览器申请一次性加入凭证，建立 `/ws/voice`，网关创建独立 TeamSpeak 客户端。控制消息通过 WebSocket 传输；语音支持 WebSocket 兼容路径和可选 WebRTC 路径。屏幕媒体使用独立连接，网关负责共享状态和信令。

## 修改方向与验收标准

### 01 统一构建命令与 CI 验证入口

**现状与位置：** [根目录 package.json](../package.json) 已通过 `npm run verify` 串联测试、后端编译和前端构建；`web:build` 委托给[前端 build](../web/package.json)，包含 `vue-tsc --noEmit`。[ci.yml](../.github/workflows/ci.yml) 覆盖 `dev`、`master`、PR、手动调用及工作流复用；镜像发布与发布包工作流已经依赖这套验证。

**后续方向：** 保留当前统一入口，后续新增测试和模块沿用它。SDK 准备、原生 Opus 重建与前端依赖安装仍是必要步骤。涉及发布脚本时，另行验证 Windows、Linux 发布包；CI 中 Docker 健康检查成功不等于这些发布包或语音链路已经验证。

**验收标准：** 本地与 CI 使用一致的前端类型检查和构建流程；类型错误、测试失败会使验证失败；开发分支、PR、发布分支及标签的触发范围有明确说明。

### 02 补齐会话与媒体关键行为测试

**现状与位置：** 当前根目录 `test` 脚本显式列出 18 个测试文件。凭证、身份占用、会话清理、目录合并和重连策略已有基础测试；协议、前端实际 composable 及屏幕共享控制器已有补充测试。本地共 69 项测试通过。尚缺真实浏览器到 TeamSpeak 的完整连接验证和 WebRTC 语音回退验证；模拟浏览器边界的生命周期测试不能替代真实媒体测试。尚未测量覆盖率。

**修改方向：** 优先为即将拆分的模块建立行为基线。覆盖加入凭证过期及重复消费、会话重复清理、目录快照与实时事件合并、重连成功与失败、WebRTC 失败回退、屏幕共享退出后的资源释放。通过可替换的时钟、传输和 SDK 边界验证正常与异常路径；真实 TeamSpeak、浏览器媒体和 Android 行为另设可重复执行的集成验证步骤。

**下一批优先用例：** 扩展已有旧连接文本消息和采集取消测试，覆盖迟到的二进制音频帧、WebRTC 协商失败后回到 WebSocket 语音，以及连续连接、断开后解码器、播放源和伴奏资源没有残留。先复现或建立断言，再实施对应修改。

**验收标准：** 核心测试能在 CI 中运行；测试能够发现重复消费、重复清理、状态不同步和回退失败等行为回归；需要设备或真实服务的步骤记录环境与结果，不以类型检查或 HTTP 健康检查代替音频验证。

### 03 集中前后端协议契约

**现状与位置：** 已新增 [src/shared](../src/shared/)，集中成员、频道、事件、音频统计和皮肤类型，并定义按命令区分的载荷及服务端消息校验。[useVoiceWebSocket.ts](../web/src/composables/useVoiceWebSocket.ts) 的 `handleMessage` 已改为接收 `unknown` 并调用 `parseServerMessage`，发送入口已约束命令与载荷；服务端发送消息也使用公共类型。原 [voice-protocol.ts](../src/server/voice-protocol.ts) 和 [screen-share.ts](../src/server/screen-share.ts) 保留转导出入口。迁移结果及验证范围见文末。

**修改方向：** 在已有迁移上收尾：逐项核对实际发送字段与接收校验，保留旧客户端的可选字段、数字频道标识和默认值行为；明确未知消息、非法消息及列表中非法条目的处理方式。用真实消息样本补充契约测试，避免只用类型定义生成样本。共享目录保持无 Node.js、DOM 或 Vue 运行时依赖，并验证 Vite 开发服务器、前后端生产构建和 Android 打包都能解析它。后端 `rootDir` 为 `src`，当前放置位置与编译边界相符。

**验收标准：** 已迁移消息的字段与类型只有一处权威定义；非法消息得到明确处理；现有错误码、请求标识和旧客户端兼容行为不因整理而变化；后端及前端均可独立构建。

### 04 拆分前端语音核心模块

**现状与位置：** [useVoiceWebSocket.ts](../web/src/composables/useVoiceWebSocket.ts) 已从 2,976 行降至约 2,266 行，屏幕共享迁至 [screen-share.ts](../web/src/voice/screen-share.ts)。连接、凭证请求、麦克风采集、降噪、播放、WebRTC 语音、伴奏和语音统计仍需进一步拆分。

**修改方向：** 暂时保留现有 composable 作为页面调用入口，逐项提取连接与命令传输、麦克风处理、远端播放、WebRTC 语音、屏幕共享及统计模块。先明确各模块拥有的状态和资源，再移动实现，避免所有模块相互读取同一个大型可变对象。每次只迁移一项职责，并明确初始化、停止和销毁的责任。

建议的模块边界如下，具体文件名在实施时确定：

| 模块 | 拥有的资源和状态 | 对外职责 |
| --- | --- | --- |
| 连接与命令 | WebSocket、连接代次、请求超时、待响应命令 | 连接、发送、处理确认及取消请求 |
| 麦克风与伴奏 | 音轨、AudioContext、处理节点、设备选择 | 采集、静音、切换设备、停止采集 |
| 远端播放 | 成员解码器、播放队列、音量节点 | 接收音频、更新音量、清理单个成员或全部播放 |
| WebRTC 语音 | PeerConnection、协商状态、混音及播放资源 | 建立语音通道、失败回退、释放通道 |
| 屏幕共享 | 采集音轨、参与者连接、ICE 配置、共享状态 | 开始、观看、信令处理和退出 |

**已修复的细节：** 旧 WebSocket 消息现在同时校验连接代次、当前 socket 和打开状态；主动断开、异常关闭及服务端断连事件共用资源释放路径。屏幕共享 ICE 配置已改为实例所有，异步协商和统计结果在所属连接失效后不再写回。麦克风授权迟到时释放音轨并取消旧操作，新连接可以独立申请采集。相关问题已通过先失败后通过的回归测试验证；其他音频资源仍需继续检查。

**验收标准：** 页面调用接口保持兼容，或有范围明确的迁移；连接、断开、重连、设备切换及 WebRTC 回退行为保持一致；音轨、解码器、定时器和事件监听具有明确清理路径，重复连接不会累计资源。

### 05 拆分服务端实时桥接模块

**现状与位置：** [voice-bridge.ts](../src/server/voice-bridge.ts) 当前为 2,135 行，同时承担连接接入、会话编排、事件同步、命令处理、音频统计和跨端屏幕共享协调。项目已经存在 `SessionManager`、`DirectorySynchronizer`、协议解析和 WebRTC 音频模块，工作区也已接入公共发送消息类型。

**修改方向：** 保留 `VoiceBridge` 的接入与组装职责，沿现有边界提取命令处理、目录与成员事件协调、音频转发、屏幕共享协调。复用现有状态机和清理机制，明确断开、踢出、管理员终止和网关关闭等路径的责任归属。

**建议切入顺序：** 先提取目录展示转换、错误分类及统计快照等输入输出明确的函数；再提取命令处理；最后迁移涉及服务器、频道和参与者状态的屏幕共享协调。会话准入与清理继续由现有 `SessionManager` 管理，避免拆出第二套会话状态。音频转发的拆分需要同时验证队列上限和节拍行为。

**验收标准：** 一次性凭证、身份占用限制、并发会话上限和重连策略保持原有行为；清理操作可安全重复执行；屏幕共享仍遵守所属服务器、频道及参与者校验；语音热路径保留有界缓冲，不新增逐帧持久化日志。

### 06 拆分页面组件与管理页逻辑

**现状与位置：** [WebClient.vue](../web/src/views/WebClient.vue) 当前为 1,208 行，已经使用多个业务 composable，但仍保留较多模板和组装逻辑。[AdminView.vue](../web/src/views/AdminView.vue) 为 1,895 行，集中多个管理功能、文案和样式。

**修改方向：** 网页客户端按加入表单、频道树、聊天区、音频设置和弹窗等稳定界面边界拆组件；管理页按服务器设置、会话、邀请、皮肤和诊断等功能拆分。将数据请求和业务状态与展示分开，优先复用已有 composable，避免重建一套平行状态。

`AdminView.vue` 还集中多语言文案，可先迁入专门的管理页文案模块。路由目前在 [main.ts](../web/src/main.ts) 中同步导入客户端、管理页和演示页，可评估按路由延迟加载；实施前后比较首屏产物和加载行为，不仅为消除包体积提示而拆包。

**验收标准：** 路由、交互、错误反馈和语言切换保持一致；皮肤公开接口 `data-ws-part` 与主题层叠关系保持兼容；验证主要页面在桌面和移动尺寸下的布局，不以组件文件变短代替行为验收。

### 07 明确 Android 平台边界与验证范围

**现状与位置：** 已提交的 Android 预览包含[移动网关](../src/mobile/index.ts)、[移动资源打包](../mobile/pack.mjs)、Capacitor 启动逻辑及 [Opus 适配](../src/server/opus-codec.ts)。本地网关仅监听 `127.0.0.1`，当前关闭 WebRTC 语音。服务端使用原生 Opus，移动端使用 `opusscript`。

[mobile/README.md](../mobile/README.md) 记录内嵌运行时为 Node.js 18.20.4，而 SDK 声明要求 Node.js 20.19 或更高；文档同时记录真机连接、后台音频及原生屏幕共享仍待验证或实现。这些是现有文档记录，本轮未重新验证设备和 SDK 运行情况。

**修改方向：** 明确服务器、浏览器和 Android 的启动与能力差异，将平台启动逻辑从通用前端入口中分离。保留独立的编解码适配边界，按实际可用能力向页面暴露功能。先验证运行时兼容性与双向语音，再决定运行时升级或适配方案。后台前台服务、MediaProjection 等新增能力单独规划，避免与代码搬迁混合。

**具体待办：** `startAndroidGateway` 成功后移除消息监听器，但错误、超时和异常路径没有对应的移除逻辑，应在拆分时统一释放监听器及计时器，并测试启动失败与重试。构建说明应补全 `web/` 依赖安装步骤。运行时兼容性须记录实际 SDK 连接结果；不能由健康检查和编解码冒烟结果推导全部 SDK 路径兼容。

**验收标准：** 普通网页和服务端无需移动端运行时即可启动；Android 构建输入与依赖安装步骤完整；真实设备验证连接、双向语音、断线恢复和资源释放；明确记录后台音频与屏幕共享的支持状态，尚未验证的能力继续标注为预览限制。

### 09 整理源码与本地产物边界

**现状与位置：** 根目录存在多份部署压缩包、`release-artifacts/`、参考素材和本地辅助内容，部分显示为未跟踪文件；已有 `.gitignore` 和 `.dockerignore` 对产物的处理范围也不同。

**修改方向：** 先列出需要版本管理的源码、保留的发布产物、运行数据、参考素材及实验脚本，再规划目录和忽略规则。新增 Android 路径时同步检查 Docker 构建上下文，避免把移动依赖或构建缓存带入服务端镜像构建。保留有用途的 SDK 准备和中继验证脚本，并注明用途。

当前 `.gitignore` 已忽略多项 Android 构建目录，`.dockerignore` 未逐项对应移动依赖及 Android 缓存，应检查实际构建上下文后补齐。`.local-opus-hook.cjs` 用缓冲区原样复制替代 Opus 编解码，只能作为特定实验的替身；应明确用途并隔离于正式启动、发布和媒体验收流程。

**验收标准：** 常规构建产物和缓存不再干扰源码变更检查；源码及必要资源没有被误忽略；构建与打包不依赖未声明的本地文件。归档或清理前确认用途及保留位置，不按未跟踪状态直接删除文件。
