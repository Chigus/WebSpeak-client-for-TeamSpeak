## 历史已修复的异步边界

下列三类风险已通过实际 composable 和桥接编排的回归测试复现并修复。浏览器、SDK 和 WebRTC 的外部边界使用替身；真实媒体链路仍需集成验收。

| 位置 | 原问题 | 修复与验证场景 |
| --- | --- | --- |
| `useVoiceWebSocket.ts` 的 `startAccompaniment` | 迟到的授权或约束结果会写回当前伴奏状态；旧音轨结束事件可能停止新采集 | 采集绑定会话、peer 和操作代次；取消后释放迟到音轨，结束监听仅处理所属流。覆盖断开、停止、交错授权和旧结束事件 |
| 同文件的 `peer.ontrack`、`applyWebRtcAnswer` 与播放恢复 | 旧协商或音轨回调可能覆盖新连接，迟到的播放失败可能恢复已清除的提示；协商计时器未立即清理 | 回调绑定 peer 和连接，播放结果绑定音频元素；关闭时清理 answer 与 ICE 等待。覆盖旧成功或失败结果、新旧播放、正常协商和失败后的 PCM 回退 |
| `voice-bridge.ts` 的 `handleWebRtcOffer` | 等待 SDK 或旧 peer 关闭期间结束会话，仍可能创建新 peer；旧协商和音频事件会污染当前状态 | 统一 `stopWebRtc` 使旧协商立即失效，等待后核验当前会话及协商代次；仅当前 peer 可发送 answer、音频和活动状态。覆盖会话移除、stop、交错 offer、旧错误和统计 |

**后续方向：** 保留当前统一入口，后续新增测试和模块沿用它。SDK 准备、原生 Opus 重建与前端依赖安装仍是必要步骤。涉及发布脚本时，另行验证 Windows、Linux 发布包；CI 中 Docker 健康检查成功不等于这些发布包或语音链路已经验证。
