# WebSpeak 代码待修改清单与修改方向

本文聚焦 `webspeak-webclient`，整理代码结构、待修改问题、大致修改方向、优先级和验收条件。前端 WebRTC 传输与播放、连接控制和命令等待已提取；命令发送异常清理、凭证请求取消与超时等问题已修复，当前通过 300 项测试及前后端构建。

后续继续整理入口中的诊断与消息状态边界，并拆分页面组件。真实 TeamSpeak、Android 真机与发布包检查独立验收，不能由模拟边界测试或构建通过推定完成。前轮只记录的整理结果保留在文中；本批为其后的实施与验证。

## 连接与命令问题的修复结果

### 04-H 命令发送异常立即清理等待资源

当前实现：[commands.ts](<USER_HOME>/Desktop/othercode/teamspeakclient4web/webspeak-webclient/web/src/voice/commands.ts)。原入口先创建默认 8 秒计时器、登记等待，再发送命令。同步发送抛错后 Promise 拒绝，但登记和计时器未立即清理。本批通过发送故障注入复现该缺口。

已实施：每条命令拥有统一且幂等的结束函数，成功、服务端错误、发送异常、超时及断开都通过它清理。确认等待绑定原 socket 与连接代次，保留默认 8 秒期限、共享命令类型和现有调用接口。

已验证：正常确认、服务端拒绝及错误码、发送抛错、超时、断开、重复回复、已排队的旧期限和旧 socket 回复；发送失败后计时器立即移除，旧操作不影响替代连接的命令。

### 04-I 加入凭证请求可取消且等待有期限

当前实现：[connection.ts](<USER_HOME>/Desktop/othercode/teamspeakclient4web/webspeak-webclient/web/src/voice/connection.ts)。原请求只有代次检查，没有取消信号和应用层期限；请求或响应体迟迟不返回时，页面持续处于连接中。原 socket 关闭异常还会跳过后续页面状态清理。本批已通过边界替身复现。

已实施：连接控制器持有取消器、15 秒期限、socket 和连接代次。期限覆盖偏好就绪、HTTP 请求及响应体；新连接和断开立即取消旧请求，旧期限与迟到响应不能写回。socket 关闭前解绑所属监听，关闭异常不妨碍其余状态清理。超时用 `REQUEST_TIMEOUT` 和五语提示说明网关等待失败。

已验证：请求无响应、响应体挂起、主动取消、连续连接不同目标、取消后迟到成功或失败、旧期限、socket 关闭异常和网关关闭码。邀请、身份、频道、密码和中继参数保持一致。浏览器取消不撤销服务端已执行的邀请使用或凭证签发，服务端的有效期和一次性使用规则保持不变。

## 近期修复的浏览器媒体问题

### 04-E 保留可用发送链并完整清理失败候选

修改前位置：`c9740c4` 中 [useVoiceWebSocket.ts](../web/src/composables/useVoiceWebSocket.ts) 的混音创建、替换和伴奏启停函数，原第 752–918 行。当前实现位于 [webrtc-input.ts](../web/src/voice/webrtc-input.ts) 和 [accompaniment.ts](../web/src/voice/accompaniment.ts)。

原实现的顺序及缺口：

- `createWebRtcMixStream` 先调用 `stopWebRtcMix`，其中会停止当前输出音轨；之后才创建新节点并调用 `sender.replaceTrack`。创建或替换失败时，旧音轨已经结束，没有可用旧链供回滚。
- 更换伴奏时，在混音接入成功前就停止旧伴奏，并发送 `active: true`。失败后再发送 `false`，无法保留原本正常的伴奏；错误统一归为 `permission`，也不能区分用户授权与音频处理失败。
- 混音节点先在局部变量中创建，之后才写入清理函数使用的引用；如果中途创建或连接失败，已取得的候选节点及输出音轨缺少完整释放路径。
- 停止伴奏也会重建整个混音并替换发送轨道，因而停止操作同样依赖新节点分配成功。

本批通过故障注入实际复现旧发送轨道结束、旧伴奏丢失、部分节点及输出音轨未释放、停止依赖新分配，以及混音节点释放异常中断会话清理。测试使用实际 composable 和浏览器边界替身，不代表已测真实浏览器的故障频率或音质。

已实施：每个 WebRTC peer 保持稳定输出轨道，仅接入或移除伴奏源；新源连接成功后再解除旧源并停止旧采集。混音模块拥有节点和输出流，独立释放部分分配及关闭资源。只有接入成功后才更新活动状态；音频处理失败使用独立错误码和五语提示，可选内容提示失败不再遗留采集。

已验证：节点分配或连接失败保留原麦克风输出与旧伴奏；启停伴奏不结束或替换发送轨道；停止不依赖新输出分配；候选失败和重复清理释放所属资源。麦克风静音和音量设置在启停期间保持有效，伴奏不经过麦克风降噪与增益，也不额外添加固定衰减。

### 04-F 停止操作立即释放已取得的候选采集

位置：[accompaniment.ts](../web/src/voice/accompaniment.ts)，由语音入口调用；回归位于 [voice-session.test.mjs](../web/test/voice-session.test.mjs)。以下描述修改前的行为。

`getDisplayMedia` 返回后，候选 `nextStream` 在等待 `applyConstraints` 期间仍是局部变量。停止或断开只清理已提交的 `accompanimentStream` 并使代次失效；候选流需等约束 Promise 结束，执行后续失效检查才被停止。现有取消用例也是先结束约束等待，再断言音轨已停止，没有覆盖立即释放。

此外，音轨的 `ended` 监听在约束等待后才注册，提交前也没有检查 `readyState`。若用户在等待期间结束采集，代码仍可能将已结束的音轨标记为活动。

已实施：伴奏控制器同时拥有当前流和已取得但未提交的候选流。停止、断开或新操作取代旧操作时，立即释放候选资源；仍未返回的授权请求在结果到达时立即释放。操作绑定原混音目标与代次，提交前复核目标和音轨状态，旧结束事件不能停止新采集。

已验证：约束 Promise 未完成时音轨已经停止；等待期间结束采集不会发送活动状态；迟到授权和旧失败不影响新伴奏。现有四项伴奏用例继续保留，其中取消用例增加立即释放断言；另验证无音频来源失败保留旧伴奏、断开清除旧错误，以及采集处理约束与五语错误映射。

### 04-G 电平监测失败不影响语音与后续连接

位置：[microphone-meter.ts](../web/src/voice/microphone-meter.ts)，由语音入口的监测启停函数组装。

原实现只在全部节点连接完成后才记录清理引用，分析器分配或连接失败会遗留先前创建的节点。计时器回调读取全局分析器引用，已排队的旧回调会读取替代连接的分析器并更新电平；读取异常没有受控处理，释放异常也可能中断 peer 和麦克风清理。五项故障用例均在修复前复现。

已实施：每个监测实例独立拥有节点与计时器，停止先使回调失效，再逐项释放资源。准备或读取失败只停止电平监测，清除电平与发言提示，保留麦克风流和语音 peer。已验证 512 点采样、50 ms 周期、原有 RMS 电平比例及上限保持一致；此处不声称真实设备的电平与音质已验收。
