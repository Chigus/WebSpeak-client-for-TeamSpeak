# WebSpeak 代码待修改清单与修改方向

本文记录 `webspeak-webclient` 的当前代码边界、待修改事项、大致修改方向及验收标准。清单最初仅做记录，现根据“开始施工，直到所有问题修复”的目标分批实施；各批次的实际验证及剩余限制见文末。

当前构建与 CI 入口已经统一，主要共享协议、前端屏幕共享和四个服务端桥接子模块已经拆出。剩余工作优先围绕媒体异步操作与资源清理建立验证，再拆分前后端语音核心和页面。Android 启动拆分及产物忽略规则已有未提交实现，需要验收，不能重复列为尚未开始。

## 已验证并修复的异步边界

下列三类风险已通过实际 composable 和桥接编排的回归测试复现并修复。浏览器、SDK 和 WebRTC 的外部边界使用替身；真实媒体链路仍需集成验收。

| 位置 | 原问题 | 修复与验证场景 |
| --- | --- | --- |
| `useVoiceWebSocket.ts` 的 `startAccompaniment` | 迟到的授权或约束结果会写回当前伴奏状态；旧音轨结束事件可能停止新采集 | 采集绑定会话、peer 和操作代次；取消后释放迟到音轨，结束监听仅处理所属流。覆盖断开、停止、交错授权和旧结束事件 |
| 同文件的 `peer.ontrack`、`applyWebRtcAnswer` 与播放恢复 | 旧协商或音轨回调可能覆盖新连接，迟到的播放失败可能恢复已清除的提示；协商计时器未立即清理 | 回调绑定 peer 和连接，播放结果绑定音频元素；关闭时清理 answer 与 ICE 等待。覆盖旧成功或失败结果、新旧播放、正常协商和失败后的 PCM 回退 |
| `voice-bridge.ts` 的 `handleWebRtcOffer` | 等待 SDK 或旧 peer 关闭期间结束会话，仍可能创建新 peer；旧协商和音频事件会污染当前状态 | 统一 `stopWebRtc` 使旧协商立即失效，等待后核验当前会话及协商代次；仅当前 peer 可发送 answer、音频和活动状态。覆盖会话移除、stop、交错 offer、旧错误和统计 |

## 修改方向与验收标准

### 01 统一构建命令与 CI 验证入口

**现状与位置：** [根目录 package.json](../package.json) 已通过 `npm run verify` 串联测试、后端编译和前端构建；`web:build` 委托给[前端 build](../web/package.json)，包含 `vue-tsc --noEmit`。[ci.yml](../.github/workflows/ci.yml) 覆盖 `dev`、`master`、PR、手动调用及工作流复用；镜像发布与发布包工作流已经依赖这套验证。

**后续方向：** 保留当前统一入口，后续新增测试和模块沿用它。SDK 准备、原生 Opus 重建与前端依赖安装仍是必要步骤。涉及发布脚本时，另行验证 Windows、Linux 发布包；CI 中 Docker 健康检查成功不等于这些发布包或语音链路已经验证。

**验收标准：** 本地与 CI 使用一致的前端类型检查和构建流程；类型错误、测试失败会使验证失败；开发分支、PR、发布分支及标签的触发范围有明确说明。

### 02 补齐会话与媒体关键行为测试

**现状与位置：** 当前根目录 `test` 脚本显式列出 24 个测试文件，118 项测试及前后端构建通过。新增的桥接编排测试替换 SDK 与 WebRTC I/O，前端测试加载实际 composable，覆盖伴奏取消、协商失效、播放资源清理，以及协商或音轨挂载失败后的 PCM 回退。Android 启动有 7 项测试。尚缺真实浏览器到 TeamSpeak 的完整连接及 WebRTC 回退验证；模拟浏览器边界的生命周期测试不能替代真实媒体测试。尚未测量覆盖率。

**修改方向：** 优先为即将拆分的模块建立行为基线。覆盖加入凭证过期及重复消费、会话重复清理、目录快照与实时事件合并、重连成功与失败、WebRTC 失败回退、屏幕共享退出后的资源释放。通过可替换的时钟、传输和 SDK 边界验证正常与异常路径；真实 TeamSpeak、浏览器媒体和 Android 行为另设可重复执行的集成验证步骤。

**下一批优先用例：** 在已完成的协商与伴奏回归上，覆盖迟到的二进制音频帧、麦克风测试录音、连续连接后的解码器与播放源清理，以及设备切换。服务端音频需要覆盖慢客户端背压、突发帧和延迟调度时的队列上限。随后补充真实浏览器和 TeamSpeak 的回退及双向语音验证。

**验收标准：** 核心测试能在 CI 中运行；测试能够发现重复消费、重复清理、状态不同步和回退失败等行为回归；需要设备或真实服务的步骤记录环境与结果，不以类型检查或 HTTP 健康检查代替音频验证。

### 03 集中前后端协议契约

**现状与位置：** 已新增 [src/shared](../src/shared/)，集中成员、频道、事件、音频统计和皮肤类型，并定义按命令区分的载荷及服务端消息校验。[useVoiceWebSocket.ts](../web/src/composables/useVoiceWebSocket.ts) 的 `handleMessage` 已改为接收 `unknown` 并调用 `parseServerMessage`，发送入口已约束命令与载荷；服务端发送消息也使用公共类型。原 [voice-protocol.ts](../src/server/voice-protocol.ts) 和 [screen-share.ts](../src/server/screen-share.ts) 保留转导出入口。迁移结果及验证范围见文末。

**修改方向：** 在已有迁移上收尾：逐项核对实际发送字段与接收校验，保留旧客户端的可选字段、数字频道标识和默认值行为；明确未知消息、非法消息及列表中非法条目的处理方式。用真实消息样本补充契约测试，避免只用类型定义生成样本。共享目录保持无 Node.js、DOM 或 Vue 运行时依赖，并验证 Vite 开发服务器、前后端生产构建和 Android 打包都能解析它。后端 `rootDir` 为 `src`，当前放置位置与编译边界相符。

**明确的剩余入口：** `webrtcOffer` 与 `webrtcStop` 仍由前端直接拼接 JSON，服务端在 `voice-bridge.ts` 中分别通过 `parseWebRtcOffer`、`isWebRtcStopMessage` 解析，尚未纳入共享的客户端控制消息契约。将其独立建模并统一校验，同时保留已有 SDP 长度限制、可选静音字段和错误行为，不必强行混入普通业务命令执行器。

**验收标准：** 已迁移消息的字段与类型只有一处权威定义；非法消息得到明确处理；现有错误码、请求标识和旧客户端兼容行为不因整理而变化；后端及前端均可独立构建。

### 04 拆分前端语音核心模块

**现状与位置：** [useVoiceWebSocket.ts](../web/src/composables/useVoiceWebSocket.ts) 当前约 2,336 行，屏幕共享已迁至 [screen-share.ts](../web/src/voice/screen-share.ts)。连接、凭证请求、麦克风采集、降噪、播放、WebRTC 语音、伴奏和语音统计仍需进一步拆分。

**修改方向：** 暂时保留现有 composable 作为页面调用入口，逐项提取连接与命令传输、麦克风处理、远端播放、WebRTC 语音、屏幕共享及统计模块。先明确各模块拥有的状态和资源，再移动实现，避免所有模块相互读取同一个大型可变对象。每次只迁移一项职责，并明确初始化、停止和销毁的责任。

建议的模块边界如下，具体文件名在实施时确定：

| 模块 | 拥有的资源和状态 | 对外职责 |
| --- | --- | --- |
| 连接与命令 | WebSocket、连接代次、请求超时、待响应命令 | 连接、发送、处理确认及取消请求 |
| 麦克风与伴奏 | 音轨、AudioContext、处理节点、设备选择 | 采集、静音、切换设备、停止采集 |
| 远端播放 | 成员解码器、播放队列、音量节点 | 接收音频、更新音量、清理单个成员或全部播放 |
| WebRTC 语音 | PeerConnection、协商状态、混音及播放资源 | 建立语音通道、失败回退、释放通道 |
| 屏幕共享 | 采集音轨、参与者连接、ICE 配置、共享状态 | 开始、观看、信令处理和退出 |

**已修复的细节：** 旧 WebSocket 消息现在同时校验连接代次、当前 socket 和打开状态；主动断开、异常关闭及服务端断连事件共用资源释放路径。屏幕共享 ICE 配置已改为实例所有，异步协商和统计结果在所属连接失效后不再写回。麦克风授权迟到时释放音轨并取消旧操作，新连接可以独立申请采集。相关问题已通过先失败后通过的回归测试验证；其他音频资源仍需继续检查。

**建议切入顺序：** 伴奏和 WebRTC 的失效检查已经补齐；继续提取远端播放、麦克风及伴奏、WebRTC 语音，最后收拢连接与命令。每个控制器显式拥有其音轨、节点、计时器和取消标识；现有 `releaseSessionResources` 保持统一清理入口。保留已建立的行为断言，并核验尚未覆盖的录音、设备切换和解码器路径。

**验收标准：** 页面调用接口保持兼容，或有范围明确的迁移；连接、断开、重连、设备切换及 WebRTC 回退行为保持一致；音轨、解码器、定时器和事件监听具有明确清理路径，重复连接不会累计资源。

### 05 拆分服务端实时桥接模块

**现状与位置：** [voice-bridge.ts](../src/server/voice-bridge.ts) 当前约 1,108 行。命令执行、目录展示转换、统计快照和屏幕共享协调已分别拆至独立模块。主模块仍负责接入、会话编排、SDK 事件与音频转发；后续继续明确音频热路径及目录事件编排的边界。

**修改方向：** 保留 `VoiceBridge` 的接入与组装职责，沿现有边界提取命令处理、目录与成员事件协调、音频转发、屏幕共享协调。复用现有状态机和清理机制，明确断开、踢出、管理员终止和网关关闭等路径的责任归属。

**下一步边界：** 目录展示、错误分类、统计快照、命令处理和屏幕共享协调已提取；WebRTC 协商与会话终止的交错行为已有修复和测试。下一步独立整理 WebSocket 音频编解码及转发，再处理 SDK 目录事件的订阅与解绑。会话准入与清理继续由现有 `SessionManager` 管理，避免拆出第二套会话状态。

音频整理须保留当前 WebSocket 下行背压阈值 `4,096` 字节，以及 `webrtc-audio.ts` 中每位说话者最多 `4` 帧的混音队列、迟到帧丢弃和调度节拍。是否调整这些参数应由音频测试决定，不随文件拆分顺带更改。已有子模块测试覆盖频道及服务器隔离、共享者与观看者信令权限、目录大整数标识、成员移动和命令回执；真实 SDK 会话和媒体集成验收仍待完成。

**验收标准：** 一次性凭证、身份占用限制、并发会话上限和重连策略保持原有行为；清理操作可安全重复执行；屏幕共享仍遵守所属服务器、频道及参与者校验；语音热路径保留有界缓冲，不新增逐帧持久化日志。

### 06 拆分页面组件与管理页逻辑

**现状与位置：** [WebClient.vue](../web/src/views/WebClient.vue) 当前为 1,208 行，已经使用多个业务 composable，但仍保留较多模板和组装逻辑。[AdminView.vue](../web/src/views/AdminView.vue) 为 1,895 行，集中多个管理功能、文案和样式。

**修改方向：** 网页客户端按加入表单、频道树、聊天区、音频设置和弹窗等稳定界面边界拆组件；管理页按服务器设置、会话、邀请、皮肤和诊断等功能拆分。将数据请求和业务状态与展示分开，优先复用已有 composable，避免重建一套平行状态。

`AdminView.vue` 还集中多语言文案，可先迁入专门的管理页文案模块。路由目前在 [main.ts](../web/src/main.ts) 中同步导入客户端、管理页和演示页，可评估按路由延迟加载；实施前后比较首屏产物和加载行为，不仅为消除包体积提示而拆包。

**管理请求边界：** `AdminView.vue` 的 `getJson`、`sendJson` 返回 `Promise<any>`，`parseResponse` 同时处理 JSON、错误码、401 页面切换和路由跳转。建议先提取带响应模型的管理 API 层，再按功能拆分页面状态；保留现有 CSRF 请求头、登录失效处理和密码或令牌的保留、替换、删除语义。先覆盖登录过期、保存失败和响应缺字段，再迁移展示组件。

**拆组件时的配套调整：** [skin-pack.test.ts](../web/src/services/skin-pack.test.ts) 目前通过读取固定 Vue 文件检查 `data-ws-part`。公开节点迁入子组件后，测试需要覆盖实际组件范围或渲染结果，继续验证同一套公开皮肤接口；不能为了拆分直接删除断言。网页组件继续复用现有 `useWebClient*` composable。

**已观察到的布局问题：** Android 15 模拟器的竖屏页面可以加载，但首页顶部的品牌文字与链接按钮发生重叠。页面整理时一并调整窄屏头部布局，并验证五种语言、品牌名称和按钮均可读、可点击。

**验收标准：** 路由、交互、错误反馈和语言切换保持一致；皮肤公开接口 `data-ws-part` 与主题层叠关系保持兼容；验证主要页面在桌面和移动尺寸下的布局，不以组件文件变短代替行为验收。
