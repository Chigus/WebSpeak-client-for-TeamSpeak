## 本批修复的具体问题

### 05-B 释放异常会中断 WebRTC 清理

**位置：** [webrtc-audio.ts](../src/server/webrtc-audio.ts) 的 `WebRtcAudioSession.close()`。

**原问题：** 原实现先设 `closed = true`，再依次释放资源。前面的步骤抛错会跳过后续释放，再次调用又因 `closed` 返回。故障注入已实际复现解码器异常中断清理。

**已实施：** 每项编解码器和音轨独立释放，及时清空映射与引用；单项失败继续后续资源清理，peer 关闭结果仍返回调用方。网关上层清理职责保留。

**验证：** 解码器、编码器和音轨同时抛错时，后续资源仍被释放；peer 抛错后重复调用共享原失败结果，不重复部分清理。相关测试通过。

### 05-C 并发关闭没有共享完成状态

**位置：** 同一 `close()` 方法的关闭状态与 Promise。

**原问题：** 第一次调用等待 peer 关闭期间，后续调用已返回完成。此行为已在延迟关闭用例中复现；不据此声称真实网络发生过连接重叠。

**已实施：** 第一次调用立即阻止后续媒体工作，清除计时器和队列；实际资源释放前发布关闭 Promise，后续调用等待同一结果，包括关闭失败。

**验证：** 延迟底层 peer 关闭时多个调用方均不提前完成，底层关闭只执行一次；成功和失败路径均通过测试。

### 02-B 新测试未进入统一命令

**位置：** [根目录 package.json](../package.json) 的 `scripts.test` 和 [webrtc-audio.test.ts](../src/server/webrtc-audio.test.ts)。

**原问题：** 显式测试列表遗漏该文件，CI 经 `npm run verify` 调用 `npm test` 也不会自动发现它。

**已实施：** 已将文件加入统一入口，保留现有测试框架与显式列表。

**验证：** 统一验证输出包含全部 3 项关闭测试，219 项测试及前后端构建通过。

## 剩余重构的大致方向

### 服务端音频草稿与 SDK 事件

[session-audio.ts](../src/server/session-audio.ts) 已拥有会话编码器，集中 PCM 入站、WebRTC 入站、TeamSpeak 下行、耳语路由及计数。`VoiceBridge` 已通过它转发三条音频路径，并在等待 WebRTC 关闭前使音频模块失效。已有草稿还调整了 SDK 构造失败的会话回收，以及 WebSocket 关闭监听保留，不能再将这些写成“尚未开始”。

本批已验证关闭期间迟到帧、慢客户端、突发帧、切换传输和编码失败。集成测试使用本机真实 HTTP/WebSocket 与原生 Opus，但替换了外部 SDK；通过结果只证明网关接线和本机编解码，不证明真实 TeamSpeak 连接。

头像已迁入 `MemberAvatarLoader`：心跳等待不再阻断下载，SDK 中断及会话退出使当前批次失效；旧成功和失败均不能写缓存、发消息、继续下载或解除新批次的占用。成员 ID 重用也不能获得离开者的头像。保留每批 50 位成员、后续 250 ms 间隔及可选失败语义。

接着提取 SDK 事件协调：`directorySnapshot`、`clientEnter`、`clientLeave`、`clientMoved`、`clientUpdated`、聊天及断连事件仍在桥接入口。事件在连接前注册，退出时解除所属监听，异步目录结果绑定发起会话。继续复用 `DirectorySynchronizer`、`SessionManager`、头像、命令和屏幕共享模块，避免建立第二套会话状态。

### 前端媒体与连接编排

[useVoiceWebSocket.ts](../web/src/composables/useVoiceWebSocket.ts) 继续作为页面调用入口。现有 `screen-share.ts`、`remote-playback.ts`、`microphone-test.ts`、`microphone-capture.ts` 和 `audio-sink.ts` 均保留复用。

建议按以下顺序逐项提取，具体文件名在实施时确定：

| 边界 | 应拥有的状态与资源 | 重点验收 |
| --- | --- | --- |
| 伴奏 | 授权操作、屏幕音频流、结束监听和混音接入 | 取消后释放迟到音轨；旧结束事件不能停止新伴奏 |
| WebRTC 语音 | PeerConnection、offer/answer、ICE 等待、播放元素和协商计时器 | 旧 peer 无法写回；失败恢复兼容 PCM；静音和音量语义不变 |
| 连接与命令 | WebSocket、加入凭证请求、连接代次、待确认命令和超时 | 断开取消等待；旧 socket 消息不写回；失败与重连状态一致 |

每个模块明确初始化、停止、销毁和取消职责，避免多个模块共同修改同一个大型状态对象。保留 `releaseSessionResources` 作为统一释放入口。采集层拥有麦克风流，录音测试只拥有录音器、期限和试听 URL；停止试听不能结束房间采集。设备替换继续遵循“候选处理链准备成功后才替换旧链”。

### 页面组件与共享契约

客户端先拆加入表单、频道树、聊天区、音频设置及弹窗；管理页拆服务器设置、会话、邀请、皮肤和诊断区。页面保留连接或认证编排，子组件通过明确输入与事件使用现有状态，不再各自请求同一份数据。

保持 `data-ws-part`、路由样式隔离和明暗主题兼容。[skin-pack.test.ts](../web/src/services/skin-pack.test.ts) 当前通过读取固定 Vue 文件检查公开节点，拆组件时需要同步测试读取范围或改用实际渲染结果；不能通过删除断言让迁移通过。

管理状态已独立，继续保留请求与登录会话绑定、过期结果丢弃、保存快照合并、密码和动作成组处理、皮肤写操作互斥等规则。五语文案与窄屏工具栏已实现，不重复作为缺失功能登记；组件迁移后再回归语言、键盘、草稿和布局。

共享协议不再另建平行类型。继续核对运行时解析与真实消息，特别是大整数频道标识、可选字段、未知消息和非法列表项；行为变更需要单独记录兼容范围。

真实服务和设备验收可以提前安排，不必等全部结构调整结束。一次改动只解决明确职责或行为问题，不同时更换依赖主版本、SQLite schema 和音质参数。

实施时继续保留以下约定：

- 兼容音频为 48 kHz 单声道、20 ms、1,920 字节 PCM；TeamSpeak 下行保留 3 字节头。
- WebSocket 背压阈值保留 4,096 字节；WebRTC 每位说话者最多 4 帧混音队列及 20 ms 调度节拍保持不变。浏览器远端播放保留现有 80 ms 窗口及解码队列限制；参数调整需另有音频依据。
